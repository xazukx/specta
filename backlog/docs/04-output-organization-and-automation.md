# Output Organization and Automated Generation

## Status: Fully Supported

Specta supports organizing TypeScript output into single files, multiple files mirroring Rust module structure, namespaces, and module-prefixed names. Automatic type collection and generation via tests or build scripts is also supported.

---

## Layout Modes

The `Layout` enum in `specta-typescript` controls how types are organized:

```rust
use specta_typescript::{Typescript, Layout};

Typescript::default()
    .layout(Layout::Files)          // separate files per Rust module
    // .layout(Layout::FlatFile)    // single file (default)
    // .layout(Layout::Namespaces)  // TypeScript namespaces
    // .layout(Layout::ModulePrefixedName) // flat file with prefixed names
    .export_to("./bindings", &resolved_types)
    .unwrap();
```

### `Layout::FlatFile` (Default)

All types in a single file. Errors if two types share the same name.

```rust
Typescript::default()
    .export_to("./bindings.ts", &resolved_types)
    .unwrap();
```

Output (`bindings.ts`):
```typescript
// This file has been generated by Specta. Do not edit this file manually.

export type User = { id: string; name: string };

export type Post = { title: string; author: User };
```

### `Layout::Files`

Creates a directory structure mirroring Rust modules, with one `.ts` file per module. Import statements between modules are generated automatically.

```rust
Typescript::default()
    .layout(Layout::Files)
    .export_to("./bindings", &resolved_types) // must be a directory path
    .unwrap();
```

Example output structure:
```
bindings/
├── index.ts           # root types + framework runtime
├── models/
│   ├── user.ts        # types from my_crate::models::user
│   └── post.ts        # types from my_crate::models::post
└── api/
    └── endpoints.ts   # types from my_crate::api::endpoints
```

Each file includes proper imports:
```typescript
// bindings/api/endpoints.ts
import type * as models$user from "../models/user";

export type CreateUserRequest = { name: string };
export type CreateUserResponse = { user: models$user.User };
```

Stale files (from types that no longer exist) are automatically cleaned up on re-export.

### `Layout::Namespaces`

Single file with TypeScript `namespace` blocks mirroring Rust modules.

```rust
Typescript::default()
    .layout(Layout::Namespaces)
    .export_to("./bindings.ts", &resolved_types)
    .unwrap();
```

Output:
```typescript
namespace $s$ {
    export namespace models {
        export namespace user {
            export type User = { id: string; name: string };
        }
    }
}
export import User = $s$.models.user.User;
```

> **Note**: Namespaces mode is not compatible with JSDoc output.

### `Layout::ModulePrefixedName`

Single file where type names include the full module path to avoid conflicts:

```typescript
export type models_user_User = { id: string; name: string };
export type models_post_Post = { title: string; author: models_user_User };
```

## Type Collection

### Manual Registration

Register types explicitly with `Types::register()`:

```rust
use specta::Types;

let types = Types::default()
    .register::<User>()
    .register::<Post>()
    .register::<Comment>();
// Dependencies are auto-registered — if User references Address,
// Address is included automatically without explicit registration.
```

### Automatic Collection with `specta::collect()`

Use `specta::collect()` to automatically gather all types marked with `#[derive(Type)]` across your entire crate (and dependencies). This uses the `collect` feature and `ctor` for build-time registration.

```toml
# Cargo.toml
[dependencies]
specta = { version = "2", features = ["collect"] }
```

```rust
use specta::Types;

// Automatically collects ALL types with #[derive(Type)] in the crate
let types: Types = specta::collect();
```

To exclude a type from automatic collection:

```rust
#[derive(Type)]
#[specta(collect = false)]
struct InternalOnly {
    // This type won't appear in specta::collect() results
}
```

## Automated Generation

### Option 1: Test-Based Generation (Recommended)

Create a test that generates bindings. Run it with `cargo test` to regenerate.

```rust
// tests/generate_bindings.rs
use specta::Types;
use specta_typescript::{Typescript, Layout};

#[test]
fn generate_typescript_bindings() {
    let types = specta::collect();
    let resolved = specta_serde::apply(types).unwrap();

    Typescript::default()
        .layout(Layout::Files)
        .export_to("../frontend/src/bindings", &resolved)
        .unwrap();
}
```

Run:
```bash
cargo test generate_typescript_bindings
```

This is the recommended approach because:
- Simple to set up
- Easy to run manually or in CI
- Can verify output hasn't changed using snapshot tests
- Does not slow down builds

### Option 2: Build Script (`build.rs`)

Generate bindings at build time with a `build.rs` script. Note: this requires all types to be defined in the build script or a separate crate, since `build.rs` runs before your main crate compiles.

```rust
// build.rs
fn main() {
    // Note: specta::collect() won't work here because the crate
    // hasn't been compiled yet. You must use a shared types crate.
    //
    // If your types are in a `my-types` crate:
    // let types = my_types::all_types();
    // let resolved = specta_serde::apply(types).unwrap();
    // specta_typescript::Typescript::default()
    //     .export_to("./bindings.ts", &resolved)
    //     .unwrap();
}
```

**Limitation**: `specta::collect()` relies on `ctor` which runs at program startup, not at build time. For build scripts, either:
- Put shared types in a separate crate and manually register them
- Use a binary (`main.rs`) instead of `build.rs`

### Option 3: Dedicated Binary

Create a binary that generates bindings:

```rust
// src/bin/generate_bindings.rs
fn main() {
    let types = specta::collect();
    let resolved = specta_serde::apply(types).unwrap();

    specta_typescript::Typescript::default()
        .layout(specta_typescript::Layout::Files)
        .export_to("../frontend/src/api/types", &resolved)
        .unwrap();

    println!("Bindings generated successfully.");
}
```

Run:
```bash
cargo run --bin generate_bindings
```

### Option 4: Framework Integration

If using a framework like Tauri with `specta-tauri`, the framework handles export automatically. You configure it once and bindings are generated as part of the framework's build process.

## Organizing by Crate of Origin

Types carry their Rust module path (e.g., `my_crate::models::user`). With `Layout::Files`, the directory structure mirrors this module hierarchy.

To organize types from **different crates** into separate folders:

### Approach: Module Paths Are Automatic

When you derive `Type` in different crates, each type's module path includes the crate name. With `Layout::Files`, types from `crate_a::models::User` and `crate_b::api::Request` will naturally land in separate directory trees:

```
bindings/
├── crate_a/
│   └── models/
│       └── mod.ts    # contains User
└── crate_b/
    └── api/
        └── mod.ts    # contains Request
```

### Virtual Types for Custom Organization

You can manually control where types appear using `NamedDataType::set_module_path()`:

```rust
use specta::datatype::NamedDataType;

let mut ndt = NamedDataType::new("CustomType", vec![], i32::definition(&mut types));
ndt.set_module_path("custom::path::here".into());
ndt.register(&mut types);
```

This places `CustomType` in the `custom/path/here/` directory when using `Layout::Files`.

## Complete Example

```rust
use serde::Serialize;
use specta::{Type, Types};
use specta_typescript::{Typescript, Layout};

#[derive(Type, Serialize)]
pub struct User {
    pub id: String,
    pub name: String,
    pub role: Role,
}

#[derive(Type, Serialize)]
pub enum Role {
    Admin,
    Member,
    Guest,
}

mod api {
    use super::*;

    #[derive(Type, Serialize)]
    pub struct CreateUserRequest {
        pub name: String,
        pub role: Role,
    }

    #[derive(Type, Serialize)]
    pub struct CreateUserResponse {
        pub user: User,
    }
}

fn main() {
    let types = Types::default()
        .register::<User>()
        .register::<api::CreateUserRequest>()
        .register::<api::CreateUserResponse>();

    let resolved = specta_serde::apply(types).unwrap();

    // Single file output
    Typescript::default()
        .export_to("./bindings.ts", &resolved)
        .unwrap();

    // Multi-file output organized by module
    Typescript::default()
        .layout(Layout::Files)
        .export_to("./bindings", &resolved)
        .unwrap();
}
```

## Configuration Reference

| Method | Description |
|--------|-------------|
| `.layout(Layout)` | Set output layout mode |
| `.header(str)` | Custom header for generated files (e.g., lint disable rules) |
| `.export(&types) -> Result<String>` | Export to string (not available for `Layout::Files`) |
| `.export_to(path, &types) -> Result<()>` | Export to file or directory |
